#### 3.4.1 首次解析的最小校验

订阅方收到消息后，首次验证至少检查：

1. Payload 能按 UTF-8 解码并解析为 JSON Object。
2. 上表 7 个字段均存在，且字段类型与定义一致。
3. `arm1JointAngles`、`arm2JointAngles` 均为数值数组；首次样例应能按 6 个元素完成解析，固定长度约束待确认。
4. 两个状态字段属于已知枚举；遇到未知值时先记录原值，不自行映射。
5. 三个位置字段为有限数值；动画坐标映射在单位和坐标系确认后再固化。

### 3.6. 首次发布、订阅示例与成功判定

#### 3.6.1 首次订阅前置条件

1. 订阅方到测试 Broker `47.109.20.246:1883` 的 TCP 网络已打通。
2. 已从发布方取得有效的测试用户名和密码。
3. 使用 MQTT 3.1.1，并为本次连接设置唯一 Client ID。
4. 发布方正在向 `3d/v1/device/269-00066/anima` 发布测试数据。

#### 3.6.2 命令行订阅示例

以下示例使用常见的 `mosquitto_sub` 客户端。执行时将占位凭据替换为发布方提供的测试凭据；不要把真实密码写入共享文档或脚本仓库。

```bash
mosquitto_sub -h 47.109.20.246 -p 1883 -V mqttv311 \
  -i igm-3d-test-01 \
  -u '<username>' -P '<password>' \
  -t '3d/v1/device/269-00066/anima' -q 0 -v
```

如需验证另一个设备，将 Topic 替换为 `3d/v1/device/269-00067/anima`。是否允许通过 `3d/v1/device/+/anima` 一次订阅多个设备，取决于 Broker ACL，当前不作为首次验证的前提。

#### 3.6.3 命令行发布示例

将 3.5 的 JSON Payload 保存为 UTF-8 编码的 `payload.json`。仅使用具有 Publish 权限的测试账号执行：

```bash
mosquitto_pub -h 47.109.20.246 -p 1883 -V mqttv311 \
  -i igm-3d-pub-test \
  -u '<publisher-username>' -P '<publisher-password>' \
  -t '3d/v1/device/269-00066/anima' -q 0 -f payload.json
```

发布方应使用与订阅定义完全一致的 Topic、QoS 0、`Retain=false` 和 UTF-8 JSON Payload。QoS 0 没有 PUBACK，最终以订阅端实际收到并成功解析消息作为发布链路成功依据。

#### 3.6.4 发布与订阅成功判定

同时满足以下条件，视为首次发布与订阅验证成功：

1. MQTT CONNECT 被 Broker 接受，未出现认证失败或协议版本错误。
2. Broker 对目标 Topic 返回成功的 SUBACK，授予 QoS 0，而不是失败码。
3. 在发布方确认正在发送数据的前提下，客户端收到目标 Topic 的消息。
4. 授权发布端发送示例消息时未报告错误，订阅端收到相同 Topic 的消息。
5. Payload 通过 3.4.1 的最小校验，并能用示例数据驱动至少一次动画更新。

### 3.7. 首次验证阶段的异常定位

本节只用于定位首次订阅问题，不定义正式运行期的重连、补偿或告警策略。

| 现象                     | 首次检查项                                                   |
| ------------------------ | ------------------------------------------------------------ |
| 无法建立 TCP 连接        | 核对 Broker IP、端口及网络/防火墙连通性                      |
| MQTT 连接被拒绝          | 核对 MQTT 3.1.1、用户名、密码及 Client ID 是否唯一           |
| 订阅成功但没有消息       | 确认发布方正在发布；核对 Topic 中的设备编码；注意 `Retain = false` 不会补发历史消息 |
| 收到消息但 JSON 解析失败 | 保留原始 Topic 和 Payload，核对 UTF-8、JSON 完整性及字段类型 |
| JSON 正常但动画错误      | 暂停固化映射，优先确认关节顺序、角度单位、坐标系和设备对应关系 |

#### 13.4.1 侧墙身份与模型显示解耦

每个加工台位均预置一个侧墙模型。实体、虚体和隐藏是同一模型的不同显示效果，不表示模型对象在台位之间实际移动。

`currentStatus.productId` 为字符串数组，表示初始化或算法已确认的侧墙身份归属。一个身份示例为 `["TSDCQ20260801150001"]`；无已确认身份时使用空数组 `[]`，不再使用单个字符串或 `null`。侧墙离开后，在身份归属更新之前可以暂时保留原身份。

`currentStatus.productName` 同步改为字符串数组，表示上述已确认侧墙的名称。两个数组必须同时存在，元素均为字符串，并满足以下约束：

- `productId.length == productName.length`。
- 对任意下标 `i`，`productId[i]` 与 `productName[i]` 必须表示同一个产品。
- 两个数组必须按对应关系成对维护和发布，不得独立排序造成错位。
- 无已确认身份时，两个数组同时为 `[]`，不使用单个字符串或 `null`。

两个字段仅用于业务身份和名称信息。修改、增加或清空这两个数组，均不得自动改变模型的显示、隐藏、实体或虚体效果；数组元素数量也不直接决定场景模型数量。产品快照接口（第14章）的业务位置更新同样不触发台位模型显隐。

#### 13.4.2 productDisplayCommand显示控制指令

`currentStatus.productDisplayCommand` 为String类型的模型显示控制指令。3D侧仅依据本字段决定是否刷新台位侧墙模型：

| 枚举值 | 3D侧执行要求 |
| --- | --- |
| `KEEP` | 不修改当前模型显示状态，不干预正在执行的动画 |
| `SOLID` | 将台位侧墙模型显示为实体 |
| `HIDDEN` | 隐藏台位侧墙模型 |
| `GHOST_DEPARTED` | 将模型显示为虚体，表示侧墙离开后的待处理状态 |
| `GHOST_UNIDENTIFIED` | 将模型显示为虚体，表示侧墙到达后身份尚未确认的状态 |

两个虚体枚举可以采用相同的显示效果，枚举区别用于表达触发原因，不与身份列表是否为空建立强制对应关系。

除 `KEEP` 外，其余枚举均为平台侧的显式显示指令。无论用于初始化、恢复或其他原因，3D侧均应按指定值刷新模型，不得根据身份列表或自行判断消息用途而忽略指令。

`KEEP` 不属于实际显示状态。3D侧应保留当前实体、虚体或隐藏效果，不能将实际状态覆盖为 `KEEP`。不支持的枚举值应记录异常，并保持原显示状态；不再按Boolean解释本字段。

#### 13.4.3 发布与执行约定

- 周期消息使用 `KEEP`，更新身份、台位信息及动态生产参数，不改变模型显示状态。
- 初始化、恢复或其他需要直接控制显示的消息，使用明确的实体、虚体或隐藏枚举；仅发布 `KEEP` 不能完成场景显示状态的初始化或恢复。
- 周期消息与事件消息使用同一台位 Topic。3D侧统一依据 `productDisplayCommand` 执行，不需要识别发布策略，也不为此增加策略字段。
- 身份确认后，平台可以更新身份列表并使用 `KEEP` 保留当前显示效果；不得将身份确认自动解释为显示实体。
- 消息继续携带完整台位Payload；其中 `KEEP` 仅表示本消息不操作模型显示，不代表该消息可独立恢复场景显示状态。

#### 13.4.4 天车动画与台位模型交接

平台确认侧墙转运起点和终点后，通过第7章天车动画接口发布吊运任务。天车挂载模型与台位预置模型为不同对象，3D侧通过显隐交接模拟侧墙转移：

1. 吊起阶段：隐藏起点台位模型，并显示天车挂载模型。
2. 落放阶段：隐藏天车挂载模型，并将终点台位模型显示为实体。
3. 动画完成后保留上述显示结果；后续 `KEEP` 消息不得使其恢复为动画前的状态。

平台无需根据动画时长另行发送起点隐藏、终点实体的配套指令；如平台另行发送非 `KEEP` 指令，3D侧仍应按显式指令刷新。

天车选择与任务调度不纳入本次修订，相关Topic及调度规则另行确认。

```javascript
import mqtt from "mqtt";

  password: "<password>",

subscriber.on("message", (receivedTopic, message) => {
  console.log(receivedTopic, message.toString("utf8"));
});

const publisher = mqtt.connect(url, {
  protocolVersion: 4,
  clientId: "if-13-pub-test",
  username: "<publisher-username>",
  password: "<publisher-password>",
  clean: true
});
publisher.on("connect", () => {
  publisher.publish(topic, payload, { qos: 0, retain: false });
});
```

#### 13.6.3 首次验证成功判定

同时满足以下条件，视为首次发布和订阅链路验证成功：

1. 发布端、订阅端的 MQTT CONNECT 均被 Broker 接受。
2. 订阅端收到成功 SUBACK；不是订阅失败码。
3. 发布端发送消息时客户端未报告错误。QoS 0 没有 PUBACK，最终以订阅端实际收到消息为准。
4. 订阅端收到 Topic `3d/v1/station/TS361202010101/data`，Payload 可按 UTF-8 解析为合法 JSON，字段与本接口定义一致。
5. 消息能够完成至少一次预期的动画、状态、标签、面板或事件更新。

#### 13.6.4 侧墙身份与模型显示机制验证

1. 发送完整消息，使用字符串数组形式的 `productId` 和 `productName`，校验两数组数量相等且同下标对应同一产品；数量不等或对应错位的数据不符合本接口约定。使用 `SOLID` 时，确认台位模型显示为实体。
2. 分别发送 `HIDDEN`、`GHOST_DEPARTED`、`GHOST_UNIDENTIFIED`，确认模型按指令隐藏或显示虚体，不受身份列表是否为空影响。
3. 使用 `KEEP` 成对修改或清空身份、名称数组，并更新工时字段，确认UI按对应关系更新而模型显示效果不变。
4. 在已具备吊运测试条件时，验证天车吊起、落放完成模型交接；期间及完成后发布 `KEEP`，确认不会干预动画或恢复旧显示状态。

#### 18.4.1 侧墙身份与模型显示解耦

缓存区是侧墙产品的缓存位置，没有加工行为。本接口仅包含缓存区基础信息、产品身份与模型显示控制及缓存时长，不包含加工设备、加工开始时间或加工时长等字段。缓存区侧墙模型的实体、虚体和隐藏控制沿用第13章约定，实际模型配置由3D侧确认。

`currentStatus.productId` 为字符串数组，表示初始化或算法已确认的侧墙身份归属。一个身份示例为 `["TSDCQ20260801150001"]`；无已确认身份时使用空数组 `[]`，不再使用单个字符串或 `null`。侧墙离开后，在身份归属更新之前可以暂时保留原身份。

`currentStatus.productName` 为字符串数组，表示上述已确认侧墙的名称。两个数组必须同时存在，元素均为字符串，并满足以下约束：

- `productId.length == productName.length`。
- 对任意下标 `i`，`productId[i]` 与 `productName[i]` 必须表示同一个产品。
- 两个数组必须按对应关系成对维护和发布，不得独立排序造成错位。
- 无已确认身份时，两个数组同时为 `[]`，不使用单个字符串或 `null`。

两个字段仅用于业务身份和名称信息。修改、增加或清空这两个数组，均不得自动改变模型的显示、隐藏、实体或虚体效果；数组元素数量也不直接决定场景模型数量。产品快照接口（第14章）的业务位置更新同样不触发缓存区模型显隐。

空缓存位置的productId和productName同时为[]；occupancyStartTime、carType及totalOccupancyDuration为null。初始化或恢复时发送HIDDEN，周期业务刷新发送KEEP。

#### 18.4.2 productDisplayCommand显示控制指令

`currentStatus.productDisplayCommand` 为String类型的模型显示控制指令。3D侧仅依据本字段决定是否刷新缓存区侧墙模型：

| 枚举值 | 3D侧执行要求 |
| --- | --- |
| `KEEP` | 不修改当前模型显示状态，不干预正在执行的动画 |
| `SOLID` | 将缓存区侧墙模型显示为实体 |
| `HIDDEN` | 隐藏缓存区侧墙模型 |
| `GHOST_DEPARTED` | 将模型显示为虚体，表示侧墙离开后的待处理状态 |
| `GHOST_UNIDENTIFIED` | 将模型显示为虚体，表示侧墙到达后身份尚未确认的状态 |

STAGING-01、STAGING-02的显示指令仅作用于承载的侧墙模型，不控制车体显隐或车辆运动；车体动画继续由对应的车辆动画接口处理。

两个虚体枚举可以采用相同的显示效果，枚举区别用于表达触发原因，不与身份列表是否为空建立强制对应关系。

除 `KEEP` 外，其余枚举均为平台侧的显式显示指令。无论用于初始化、恢复或其他原因，3D侧均应按指定值刷新模型，不得根据身份列表或自行判断消息用途而忽略指令。

`KEEP` 不属于实际显示状态。3D侧应保留当前实体、虚体或隐藏效果，不能将实际状态覆盖为 `KEEP`。不支持的枚举值应记录异常，并保持原显示状态；不再按Boolean解释本字段。

#### 18.4.3 发布与执行约定

- 周期消息使用 `KEEP`，更新身份、缓存区信息及缓存时长，不改变模型显示状态。
- 初始化、恢复或其他需要直接控制显示的消息，使用明确的实体、虚体或隐藏枚举；仅发布 `KEEP` 不能完成场景显示状态的初始化或恢复。
- 周期消息与事件消息使用同一缓存区 Topic。3D侧统一依据 `productDisplayCommand` 执行，不需要识别发布策略，也不为此增加策略字段。
- 身份确认后，平台可以更新身份列表并使用 `KEEP` 保留当前显示效果；不得将身份确认自动解释为显示实体。
- 消息继续携带完整缓存区Payload；其中 `KEEP` 仅表示本消息不操作模型显示，不代表该消息可独立恢复场景显示状态。

#### 18.4.4 天车动画与缓存区模型交接

平台确认侧墙转运起点和终点后，通过第7章天车动画接口发布吊运任务。天车挂载模型与缓存区侧墙模型为不同对象，3D侧通过显隐交接模拟侧墙转移：

1. 吊起阶段：当起点为缓存区时，隐藏该缓存区侧墙模型，并显示天车挂载模型。
2. 落放阶段：当终点为缓存区时，隐藏天车挂载模型，并将该缓存区侧墙模型显示为实体。
3. 动画完成后保留上述显示结果；后续 `KEEP` 消息不得使其恢复为动画前的状态。

平台无需根据动画时长另行发送起点隐藏、终点实体的配套指令；如平台另行发送非 `KEEP` 指令，3D侧仍应按显式指令刷新。

天车选择与任务调度不纳入本次修订，相关Topic及调度规则另行确认。

#### 18.6.2 WebSocket 发布与订阅示例

```javascript
import mqtt from "mqtt";
import { readFileSync } from "node:fs";

const url = "ws://47.109.20.246:8083<websocket-path>";
const topic = "3d/v1/buffer/B-01/data";
const payload = readFileSync("./payload.json", "utf8");

const subscriber = mqtt.connect(url, {
  protocolVersion: 4, // MQTT 3.1.1
  clientId: "if-18-sub-test",
  username: "<username>",
  password: "<password>",
  clean: true
});
subscriber.on("connect", () => subscriber.subscribe(topic, { qos: 0 }));
subscriber.on("message", (receivedTopic, message) => {
  console.log(receivedTopic, message.toString("utf8"));
});

const publisher = mqtt.connect(url, {
  protocolVersion: 4,
  clientId: "if-18-pub-test",
  username: "<publisher-username>",
  password: "<publisher-password>",
  clean: true
});
publisher.on("connect", () => {
  publisher.publish(topic, payload, { qos: 0, retain: false });
});
```

#### 18.6.3 首次验证成功判定

同时满足以下条件，视为首次发布和订阅链路验证成功：

1. 发布端、订阅端的 MQTT CONNECT 均被 Broker 接受。
2. 订阅端收到成功 SUBACK；不是订阅失败码。
3. 发布端发送消息时客户端未报告错误。QoS 0 没有 PUBACK，最终以订阅端实际收到消息为准。
4. 订阅端收到 Topic `3d/v1/buffer/B-01/data`，Payload 可按 UTF-8 解析为合法 JSON，字段与本接口定义一致。
5. 消息能够完成至少一次预期的动画、状态、标签、面板或事件更新。

#### 18.6.4 侧墙身份与模型显示机制验证

1. 发送完整消息，使用字符串数组形式的 `productId` 和 `productName`，校验两数组数量相等且同下标对应同一产品；数量不等或对应错位的数据不符合本接口约定。使用 `SOLID` 时，确认缓存区模型显示为实体。
2. 分别发送 `HIDDEN`、`GHOST_DEPARTED`、`GHOST_UNIDENTIFIED`，确认模型按指令隐藏或显示虚体，不受身份列表是否为空影响。
3. 使用 `KEEP` 成对修改或清空身份、名称数组，并更新缓存时长字段，确认UI按对应关系更新而模型显示效果不变。
4. 在已具备吊运测试条件时，验证天车吊起、落放完成模型交接；期间及完成后发布 `KEEP`，确认不会干预动画或恢复旧显示状态。

#### 18.6.5 首次验证异常定位

| 现象 | 首次检查项 |
| --- | --- |
| 无法建立连接 | 核对 Broker、端口、传输方式、网络和防火墙；WebSocket 还需核对握手路径 |
