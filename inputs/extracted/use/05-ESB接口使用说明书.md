# ESB 接口使用说明书

分册 V1.1｜2026-10-19｜2 项接口联合使用

配套定义：[ESB 接口定义](../版本261017/接口定义说明书五、ESB部分-1013.md)。完整 XML 报文查配套定义；本文重点说明以 MBOM 为基础构建“一墙一档”的联合使用方法。标为“建议”的策略为实施建议，原文实测不等于长期服务保证。

参考样例：[侧墙 MBOM](M000004674786-MBOM.XLS)、[物料文档关系](侧墙物料号与文档号关联表.csv)、[含文档链接的关联表](侧墙物料号与文档号关联表_含URL.xlsx)。样例用于理解关联关系和联调输入，不代表当前链接仍有效或已覆盖全部资料。

## 1. 任务范围

- **业务目标：** 以侧墙 MBOM 结构为基础，在各物料节点挂载关联的研发、工艺、生产等多格式非结构化文档，构建“一墙一档”，供用户查阅。
- **本平台角色：** 主动调用 IF-SAP-001 获取物料关联文档的最新版本信息，再调用 IF-WINDCHILL-001 获取文档链接，两接口通常串联使用。
- **输入：** 侧墙 MBOM 文件、其中各节点的物料号，以及接口环境和访问凭据。
- **输出：** 保留 MBOM 层级的物料文档关联、文档类型／名称／编号／版本、链接及获取状态，并提供下载查阅入口。
- **能力边界：** 现阶段通过 Windchill 取得链接，将文件下载保存到本地后，使用本地软件打开查阅；不支持在线浏览。
- **说明边界：** 本文讲接口的场景、调用顺序、参数来源和结果使用。MBOM 解析、具体侧墙与 MBOM 的关联、节点挂载、存储及版本管理由平台业务代码实现，不在本文展开。

## 2. 连接与公共规则

两接口均为 SOAP 1.1、HTTP POST、Basic Auth、UTF-8；Body 是 XML，不是直接 JSON。

| 接口 | 地址与格式 |
| --- | --- |
| SAP 测试 | `http://10.223.101.55:8000/ESB/SAP/SAP_MaterialAndDocumentNewQuery` |
| SAP 生产 | `http://ipass.tangche.com:30800/ESB/SAP/SAP_MaterialAndDocumentNewQuery/1.0.0` |
| SAP Content-Type | `application/xml; charset=utf-8` |
| Windchill 生产 | `http://ipass.tangche.com:30800/ESB/WINDCHILL/WINDCHILL_GeneralInterface`；测试地址未提供 |
| Windchill Content-Type | `text/xml; charset=UTF-8` |

XML 按命名空间和元素名解析，不硬编码 ns2 等前缀。相同物料或文档可合并查询，但不能合并掉 MBOM 中的不同节点。建议批量请求串行、请求间至少 200ms，沿用原文实测起点；这不是正式限流值。接口取数成功、节点挂载完成和文件可查阅分别核验。

## 3. 两接口联合使用方法

### 3.1 使用场景与完整流程

| 场景 | 何时、如何使用 |
| --- | --- |
| 首次构建一墙一档 | 导入侧墙 MBOM 后，按各节点物料调用 SAP，再按返回文档号调用 Windchill，完成资料挂载 |
| MBOM 新增或变更 | 对新增或变化物料执行联合查询，更新相关节点；同物料重复节点复用查询结果 |
| 节点资料缺失或用户要求刷新最新版 | 重新查询 SAP 文档关系和版本，再按需获取对应链接 |
| 已有文档链接失效 | 按已知文档号重新取链；若要核查最新版本，则先重新查询 SAP |

```text
读取侧墙 MBOM，保留层级与物料节点
  → 按物料号合并查询，调用 IF-SAP-001
  → 获得关联文档号及最新版本信息
  → 按文档号调用 IF-WINDCHILL-001 获取链接
  → 平台将文档资料挂载到对应 MBOM 节点，更新获取状态
  → 用户选择资料，下载保存到本地并打开查阅
```

以 MBOM 和查阅需求触发为主，不高频轮询。是否定期复核在用物料的文档版本，由项目业务需要确定；无需固定每日调用全部物料。

### 3.2 IF-SAP-001 获取物料关联文档及最新版本

1. 从 MBOM 各物料节点取得物料编号，将原始字符串填入 `request.requestInfo.PMATNR`，保留前导零。接口按单个物料调用，平台可先合并重复物料查询。
2. 使用 SOAP Envelope；request 命名空间为 `http://www.tc.com/TCSAP/Inv/MaterialAndDocumentNew/v1.0`。
3. 依原文实测，检查 HTTP 200 且存在 `Envelope/Body/response/resultInfo/DOCS`，并排除 SOAP Fault。成功响应没有 esbInfo，不能套用 MOM 判定。
4. 从 DOCS.item 取得 DOKAR（类型）、DOKNR（文档号）、DOKVR（版本）、DOKTL（部分）和 DKTXT（名称）等，并保留与原物料的关联。一个物料可关联多个文档，不能只取第一条。
5. 将每个所需文档的 DOKNR 传给 Windchill 取链；平台据此更新各对应 MBOM 节点的资料信息。

**版本说明：** 文档号与版本分别由 DOKNR、DOKVR 表达，不能仅凭文档号识别版本。原文“各文档返回最新版本”来自实测，正式保证仍需确认；样本最多 5 条不是接口条数上限。`<DOCS/>` 表示本次未取得关联文档，不删除 MBOM 节点。

### 3.3 IF-WINDCHILL-001 获取文档链接

1. 以上一步的 DOKNR 作为 docNumber。使用 SOAP Envelope，业务根 BusAdapterService，命名空间 `http://adapter.tangche.ext/`，apiName 为 `getDocSecFileInfo`。
2. 将 `{"docNumber":"实际文档号"}` 放入 requestInfo 的 CDATA，不是普通 XML docNumber 子节点，也不是直接提交 JSON Body。
3. HTTP 200 后检查 returnStatus：S 成功，return 同为 S，returnMsg 是 URL；E 为业务失败，returnMsg 是错误说明。
4. 将链接关联回原文档及物料，记录获取时间和结果，供节点展示及下载使用。相同文档可复用取链结果，但各节点的挂载关系仍应保留。

**边界：** 接口返回链接，不直接返回文件内容。链接可能临时有效，失败时受控重新取链，不无限重试。原文实测为单链接，多附件行为待确认。请求没有版本参数，附件与 SAP 记录版本的对应仍须核验，不能凭文件名保证版本。

### 3.4 节点挂载、本地查阅与异常

平台保留原 MBOM 结构，把每条文档资料关联到对应物料节点。同一物料可挂多个文档，同一文档也可关联多个物料；查询合并不能造成节点关系丢失。具体关联更新和文档管理逻辑由平台实现。

用户在节点上选择资料后，通过取得的链接下载文件到本地，使用支持该格式的软件打开。资料包括研发、工艺、生产等多种材料，不限于 PDF；不能把所有链接统一当作可在线预览的页面。

| 情况 | 处理原则 |
| --- | --- |
| SAP 无关联文档 | 节点保留，明确本次无关联资料 |
| 已有文档号，Windchill 取链失败 | 保留文档信息，标明链接未取得，不能误报为物料无文档 |
| 链接失效或文件下载失败 | 核查链接、网络和权限，按需重新取链；仍失败则记录不可用原因 |
| 文件已下载但本地无法打开 | 核查文件与本地格式支持；不能只凭 URL 获取成功认定可查阅 |
| 接口失败或节点挂载失败 | 分别记录获取／业务处理结果，保留原节点和已有资料，不以失败响应清空资料 |

文档类型、名称、编号、版本、节点关联和获取状态应可追溯。缓存、下载存储、重试及档案版本管理的具体实现不在本册规定。

## 4. 联调步骤与完成标准

1. 以提供的侧墙 MBOM 为输入，选取有文档的节点，跑通“SAP→Windchill→节点挂载→下载到本地→打开查阅”。
2. 验证重复物料节点、一物料多文档和共享文档，确保查询可复用、层级和挂载关系不丢失。
3. 验证空 DOCS、文档不存在、链接失效及下载失败；HTTP 200 的业务失败不能误判成功，资料失败不删除节点。
4. 验证 MBOM 变更、资料刷新和多格式本地查阅，核对文档号、版本、获取时间及资料状态。

**完成标准：** MBOM 层级保留，关联资料挂载到正确节点；已取得且可用的资料能够下载到本地并打开，无资料或不可用项有明确状态。仅接口成功、关系表保存或 URL 获取成功，不代表“一墙一档”查阅闭环完成。本阶段不以在线浏览作为验收项。

| 临时链接有效期、多附件行为、附件与 SAP 版本如何对应 | Windchill／ESB 方；决定取链、刷新与版本核验 |
