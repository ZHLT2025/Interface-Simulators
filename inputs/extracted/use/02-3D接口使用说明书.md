完整字段与报文查配套定义。本册按本次确认统一设备详情周期发布、车辆布尔值及产品／告警全量发布规则，旧定义相关表述待同步。轴系标定和初始化 API 等尚未确定的内容见第 5 节，不编造内部字段或接口地址。

## 1. 任务范围

- **本平台角色：** 发布方；3D 为消费方。平台从已获取的 IOT 数据及业务对象最新状态取数、转换、封装并发布。
- **输入：** 合并后的设备点位，设备／台位／产品／缓存区状态，已确认转运路径，KPI 统计结果及告警对象。
- **输出：** 对应 Topic 的完整动画消息、面板快照、全量产品／告警集合和显示指令，驱动 3D 场景更新。
- **说明边界：** 本文讲清每个 Topic 的数据来源、必要转换、封装层级和发布条件。平台对象暂无字段样例，先按业务含义描述；数据库、状态推断算法及调度代码不展开。3D 负责渲染与动画，仅保留影响双方配合的消费约定。

```text
取得 IOT 当前值及平台对象最新状态
  → 按设备、机械手或业务对象确定取数范围
  → 转换状态、类型、单位和编码，组装完整 Payload
  → 校验 Topic、对象及字段一致性，按周期或事件发布
  → 3D 消费更新，核验数据与实际展示效果
```

## 2. 连接与公共规则

| 通道 | 测试 | 生产 | 使用范围 |
| --- | --- | --- | --- |
| MQTT/TCP | `mqtt://47.109.20.246:1883` | `mqtt://10.223.101.119:1883` | 动画接口、停用标签接口 |
| MQTT/WebSocket | `ws://47.109.20.246:8083/mqtt` | `ws://10.223.101.119:8083/mqtt` | KPI、详情、产品、告警、缓存区 |

MQTT 3.1.1，账号密码，唯一 Client ID，QoS 0，Retain=false，UTF-8 JSON。WebSocket 路径按原文默认 `/mqtt`，部署时核实。

### 2.1 对象映射与取数

按设备信息表，映射如下；IGM 编号 01／02 对应 arm1／arm2，窗口打磨编号 01／02／03 对应 serialNo=1／2／3 及详情中的 robot1*／robot2*／robot3*。

| 设备／固资号 | IOT 流编码 | 发布取数关系 |
| --- | --- | --- |
| 西二 IGM／269-00066 | cqx11、cqx12 | 分别取 arm1、arm2 数据，合为该设备的一条动画或详情消息 |
| 西一 IGM／269-00067 | cqx21、cqx22 | 分别取 arm1、arm2 数据，合为该设备的一条动画或详情消息 |
| 大线打磨／999-00655 | dxdm | 该设备动画及详情 |
| 窗口打磨／999-00690 | ckdm1、ckdm2、ckdm3 | 动画分发到 serialNo=1／2／3，详情合为整机一条消息 |
| 西60米 FOOKE／046-00004 | 000000100004060013 | 按平台已关联设备状态封装；服务台位为 TS361202030101、TS361202030102 |
| 东60米 FOOKE／046-00019 | 000000100004060007 | 按平台已关联设备状态封装；服务台位为 TS361202030103、TS361202030104 |

设备号和 IOT 编码均作为字符串保留前导零。主数据有编码不等于实时数据已接入，实际可用测点仍需与 IOT 查询结果核对。Topic 中的固资号不直接使用 IOT 流编码替代。

**转换与封装：**

- IOT 消息只含变化点位，从合并后的当前值取数；按“设备编码＋参数编码”识别点位，不把一条增量消息直接作为完整 3D 消息。
- 原始 value 按参数类型解析，再按目标 JSON 类型输出；状态码按平台已确认状态映射为接口枚举。关节轴按约定顺序组装，数组和逗号分隔字符串分别按各接口定义输出。
- 关节角、滑车、龙门等位置数据取自 IOT 相关测点；轴顺序、单位、方向和零点尚未确认，不能预设换算系数，也不把 TCP 位姿直接代作关节角。
- 基础信息取平台主数据，当前产品／位置取业务关联，工时取平台计算结果，KPI 和告警取对应模块最新结果。发布环节不按每个 Topic 重复推断业务状态。
- IOT 字段的业务时间以 serverTime 为准；业务对象保留其实际更新时间。发送时间不能替代数据更新时间，跨源数据先统一时间口径。

### 2.2 发布与异常规则

| 类型 | 平台发布策略 |
| --- | --- |
| 周期动画 | 按周期读取最新完整状态；有效值不变也继续发 |
| 设备详情 | 统一按约定频率发完整消息，低频变化的基础信息按原值与动态参数一起封装；10 秒可作沿用原定义的建议值，最终周期双方约定 |
| 天车任务 | 平台算法识别出准确转运路径后，封装任务发布；不凭单个原始事件猜路径 |
| 车辆进出 | 进入发 true、离开发 false；一次确认的进出事件一次发布 |
| 产品／告警集合 | 集合内容变化后发布约定范围内全量数据，哪怕仅一个元素变化，也不能只发该变化项 |
| 台位／缓存区 | 周期消息使用 KEEP；需要直接控制显示时使用明确显示指令，均带完整 Payload |

**异常与恢复：** 记录取数、封装和发送结果，QoS 0 发布无报错不代表 3D 已处理。断连后周期数据恢复发当前值，产品／告警恢复发当前全量集合，一次性动作不盲目补播历史。必填数据缺失、解析失败或过期时记录异常；处理规则未明确前不发伪造的完整消息，不复制其他对象或填零凑数，也不向 Payload 擅增质量标志字段。

### 2.3 初始化方案

Retain=false 不向新订阅者补发保留快照。**拟采用 3D 首次进入或重连时主动调用平台 API，查询对象最新状态完成初始化，再持续消费 MQTT 更新。** API 的具体契约和实现另行安排，本册不新增具体地址、请求字段或 MQTT 请求 Topic，也不将其列为已实现接口。

初始化需取得当前业务信息及明确的模型显示状态，不能仅用 KEEP 恢复台位／缓存区显示。建议先建立 MQTT 订阅再查询状态；查询期间实时消息与快照如何衔接，须在 API 设计中明确，避免旧快照覆盖新状态。API 与 MQTT 的对象标识、取值和显示含义应一致。

## 3. 各接口使用方法

### 3.1 IF-3D-MQTT-001 IGM 焊机动画

- **场景／策略：** 展示机械手、滑车和龙门；约 1 Hz／Topic 持续发布，待机／停机仍是有效状态。
- **Topic：** `3d/v1/device/269-00066/anima`、`3d/v1/device/269-00067/anima`。
- **取数／封装：** 按 2.1 聚合两只机械手的当前状态、轴角和滑车测点；从同一整机的龙门测点取位置。封装 arm1Status、arm2Status、arm1JointAngles、arm2JointAngles、arm1CargoPos、arm2CargoPos、gantryPos 共 7 字段。
- **转换／结果：** 状态映射为作业／待机／停机；关节为数值数组，其余位置为 Number。轴系及位置转换按后续标定执行，不把样例的 0～1 范围直接当任意测点归一化公式。设备停用或服务退出才停任务；不补播旧姿态。

### 3.2 IF-3D-MQTT-002 大线打磨动画

- **场景／策略：** 展示工作状态、打磨焊缝和导轨位置，1 Hz 持续发布。
- **Topic：** `3d/v1/device/999-00655/anima`。
- **取数／封装：** 从 dxdm 当前测点和已识别设备状态取工作状态、当前打磨焊缝、导轨位置，分别封装 status、weldNo、trackPos。
- **转换／结果：** status 映射为接口枚举，weldNo 转 Number，trackPos 按标定转为场景坐标；不能直接套用面板中的字符串类型。恢复后发当前快照，不补播旧位置。

### 3.3 IF-3D-MQTT-003 窗口打磨动画

- **场景／策略：** 分别展示三个机械手；原定义 1 Hz，建议按每 Topic 1 Hz 联调并确认频率粒度。
- **Topic：** `3d/v1/device/999-00690/{serialNo}/anima`，serialNo 分别为 1、2、3。
- **取数／封装：** ckdm1、ckdm2、ckdm3 分别对应 serialNo=1、2、3；从各自测点及平台状态取得 armStatus、armJointAngles、trackPos，逐 Topic 封装。
- **转换／结果：** 状态映射为枚举，轴角转数值数组，导轨位置按标定转换；不复制另一只机械手的数据。动画三个 Topic，整机详情一个 Topic。

### 3.4 IF-3D-MQTT-004 FOOKE 动画

- **场景／策略：** 设备状态、作业台位或隔音罩到位位置变化时，事件触发一次。
- **Topic：** `3d/v1/device/{deviceCode}/anima`，deviceCode 为 046-00004、046-00019。
- **取数／封装：** status、workPosition 取平台已识别的设备工作状态和作业台位；shieldPosition 取 CV 罩体到位事件经 ROI／台位映射后的当前位置。三字段在状态更新后合为完整对象。
- **转换／结果：** 工作状态转接口枚举，实际台位转约定的位置 1／2；具体编号对应需核验。罩体到位不直接等同机床开始加工，工作状态由平台业务逻辑判断；无变化时不按 1 Hz 重复发事件。

### 3.5 IF-3D-MQTT-005 天车动画

- **场景／策略：** 平台算法识别出准确转运路径并形成有效任务后发布，一次任务一次消息。
- **Topic：** `3d/v1/device/{deviceCode}/anima`，deviceCode 为 crane1、crane2、crane3。
- **取数／封装：** 从平台确认的转运任务提取天车编码、路径起终点、是否挂载、挂载姿态和侧墙类型，封装 source、target、isMounted、mountState、carType；路径算法不在本册展开。
- **转换：** source／target 用平台位置编码，isMounted 为 Boolean，mountState、carType 按定义转枚举数值；路径结果只映射现有字段，不擅增轨迹数组。天车编码不能从单个原始视觉事件猜出。
- **模型交接：** 3D 吊起时隐藏起点模型、显示挂载模型；落放时隐藏挂载模型、显示终点实体。动画完成后保留结果。平台无需按动画时长补发配套显隐指令。
- **边界：** 报文没有任务 ID、时间或时长。内部任务先保存去重；重复、过期和重放行为须确认，不自动补播完成任务。

### 3.6 IF-3D-MQTT-006 人员作业动画

- **场景／策略：** 已确认的区域人数变化时发一次；0 人也要更新。
- **Topic：** `3d/v1/device/zone_hc/anima`。
- **取数／封装：** 从平台区域最新人数对象取区域和人数；其来源为经 ROI 映射、去重或汇总后的 CV PERSON_COUNT 结果，不直接把摄像机 ROI 编码当台位编码。
- **转换／结果：** 封装 worker_Zone 字符串、worker_Num 数值。发布当前人数，不发相对增量；未知人数不等于 0。

### 3.7 IF-3D-MQTT-007 原料车辆进出动画

- **场景／策略：** 平台根据 CV 和车辆业务状态确认型材进料车进入或离开指定区域后，各发布一次，不逐帧重复。
- **Topic：** `3d/v1/station/raw_material_car_entry/anima`。
- **取数／封装：** 从已关联车辆类别及 ROI 的业务事件取进出方向，进入发 `{"raw_material_car_entry":true}`，离开发 `{"raw_material_car_entry":false}`。
- **边界：** false 明确表示离开，不是心跳或通用复位；没有进出事件不发布。载荷变化不自动等同车辆离开，历史进出不自动重放。

### 3.8 IF-3D-MQTT-008 成品转运车辆进出动画

- **场景／策略：** 平台确认成品转运车进入或离开后发布，一次进出事件一次消息；不是把装车、进场、离场都当成同一动作。
- **Topic：** `3d/v1/station/product_car_exit/anima`。
- **取数／封装：** 从已确认车辆进出业务事件取方向，进入发 `{"material_car_entry":true}`，离开发 `{"material_car_entry":false}`。字段仍为 material_car_entry，不按 Topic 名改字段。
- **边界：** Boolean 只表达车辆进出，装车事实若未产生进出不额外发此消息；产量来自平台业务对象，不按消息条数统计。

### 3.9 IF-3D-MQTT-009 核心 KPI

- **场景／策略：** 平台统计结果因计划、完工、设备状态、开口项或统计期变化而更新后，发布最新 KPI；发布环节不另向上游重查并计算一套指标。
- **Topic：** `3d/v1/panel/kpi`。
- **取数／封装：** 从平台统计对象取得设备开机率、开口项数、计划兑现率、实际／计划完工数，转换为 uptimeRate、openItems、scheduleComplianceRate、productionCompletionStatus，一次完整发布。
- **转换／边界：** 百分比格式化为 String，openItems 为 Number，完成数按“实际/计划”封装为 String。统计口径由业务模块维护；分母为零及无数据表达需确认，不编造 0%／100%。

### 3.10 IF-3D-MQTT-010A IGM 详情

- **场景／策略：** 按约定固定周期发布整机完整详情。基础信息未变化仍按原值与动态参数一起发送，不只在数值变化时发；周期规则见 2.2。
- **Topic：** `3d/v1/device/269-00066/data`、`3d/v1/device/269-00067/data`。
- **取数／封装：** staticAttributes 取整机主数据；currentStatus 取平台设备状态、累计作业时长、关联产品及当前台位；dynamicParameters 聚合对应 IOT 流的运行模式、程序、焊接与送丝参数等。
- **转换／边界：** 按固资号和 arm1／arm2 对应取数，主／副手工艺字段按测点实际含义映射，不能把流编号直接等同电源通道编号。数值按定义多为 String；lastUpdateTime 取真实数据更新时间，不因重发改成当前时刻。

### 3.11 IF-3D-MQTT-010B 大线打磨详情

- **场景／策略：** 按约定固定周期发布整机完整详情，静态信息与动态值一并封装。
- **Topic：** `3d/v1/device/999-00655/data`。
- **取数／封装：** 基础信息取 999-00655 主数据，currentStatus 取平台设备／产品／台位及工时状态；从 dxdm 测点取模式、速度、TCP 和焊缝编号，填 operatingMode、polishSpeed、cutterSpeed、robotSpeed、TCP_X／Y／Z、weldNo 等。
- **转换／边界：** 按定义转为 String，其中 weldNo 与动画的 Number 不同；模式码及位姿按已确认映射转换，不把原始对象直接填入标量字段。

### 3.12 IF-3D-MQTT-010C 窗口打磨详情

- **场景／策略：** 按约定固定周期发布三个机械手的整机完整详情，基础信息保持原值参与每次组装。
- **Topic：** `3d/v1/device/999-00690/data`，不带机械手序号。
- **取数／封装：** 整机主数据及业务状态与 ckdm1／2／3 当前值合并，在同一条消息内分别填 robot1*、robot2*、robot3* 的模式、速度、导轨位置和轴参。
- **转换／边界：** JointsAngles 按约定轴序封装为逗号分隔 String，动画接口则是数值数组；不复用错误序列化结果，不复制别组数据凑数。

### 3.13 IF-3D-MQTT-011 台位详情与显示控制

**场景／策略：** 周期刷新身份和生产参数；事件改变显示；初始化／恢复重建显示。周期可先用 10 秒联调，原文只是举例，实际值双方确认。

**Topic：** `3d/v1/station/{stationCode}/data`，使用核实后的台位清单；周期与事件使用同一 Topic、完整 Payload。

**取数／封装：** staticAttributes 取台位主数据；currentStatus 取平台已关联的产品、加工设备、占用及加工起点；dynamicParameters 取融合 IOT 有效加工与 CV 占用后计算的工时和节拍结果。按约定格式封装时长、编码和类型，不在发布时根据一条原始 CV 事件重新推断整套状态。

**身份：** currentStatus.productId 和 productName 均为字符串数组，等长、同下标对应，成对维护；无确认身份时同时为 `[]`。身份可能在侧墙离开后暂时保留。数组内容及数量不控制模型显隐，也不决定模型数量。

**显示指令：** currentStatus.productDisplayCommand 为区分大小写的 String，适用于台位和缓存区：

| 指令 | 平台发布含义 |
| --- | --- |
| KEEP | 保留当前显示，不干预动画；不是一种实际显示状态 |
| SOLID | 显示实体 |
| HIDDEN | 隐藏侧墙模型 |
| GHOST_DEPARTED | 显示虚体，表示离开后的待处理状态 |
| GHOST_UNIDENTIFIED | 显示虚体，表示到达后身份未确认 |

**方法：**

1. 周期消息用 KEEP，同步身份、占用／加工信息和时长。身份确认后可用 KEEP 保留显示；即使本次只变身份数组，仍发布完整 Payload。
2. 初始化、恢复或需要改变显示时，用明确的实体／虚体／隐藏指令。3D 不根据身份是否为空忽略显式指令。
3. 天车动画自行完成起终点模型交接，后续 KEEP 保持交接结果。平台另发非 KEEP 时，3D 仍按显式指令刷新。
4. 未知指令记异常并保持原显示；不把 KEEP 存成实际显示状态。不要沿用旧版 hasProduct 控制显隐。

### 3.14 IF-3D-MQTT-012 产品快照

- **场景／策略：** 产品建立、身份补齐、位置／设备变化、时长和节拍状态变化后发布。
- **Topic：** `3d/v1/product`，对象内含 products 数组。
- **取数／封装：** 从平台产品集合取产品身份、物料、订单、当前台位／设备及工时，分别填入 products 中每项的 staticAttributes、currentStatus、dynamicParameters。产品身份结合 MOM 与平台关联取得，位置／工时与台位、缓存区使用同一业务结果。
- **转换：** 每个产品的 productID、productName 在本接口为 String，不套用台位身份数组；位置字段按定义转编码或名称，时长取平台结果并格式化。产品位置变化只更新业务信息，不触发模型显隐。
- **全量规则：** 任一产品变化后，重新组装平台约定发布范围内的全部产品，发送完整 `{"products":[...]}`，不能只发变化产品。确无产品时发送 `{"products":[]}`；查询失败不能伪装为空集合。具体集合范围待业务确认，发布端不自行缩减范围。

### 3.15 IF-3D-MQTT-013 设备标签（原第 15 项，停用）

- **Topic：** `3d/v1/device/{deviceCode}/min_data`，deviceCode 为固资号。
- **策略：** 标题明确停用，表内仍写联调中。当前按停用处理，不建发布任务或新订阅依赖。
- **恢复条件：** 明确恢复及与设备详情的分工后，再确认触发、空值和初始化；保留旧说明不代表继续运行。

### 3.16 IF-3D-MQTT-014 台位标签（原第 16 项，停用）

- **Topic：** `3d/v1/station/{stationCode}/min_data`。
- **策略：** 当前不发布、不自动补发；停用标签不影响台位详情运行。
- **恢复条件：** 明确恢复及与台位详情的分工后，再核对字段、空闲处理和初始化。

### 3.17 IF-3D-MQTT-015 告警事件

- **场景／策略：** 新告警及确认、处理或内容变化后发布；持续超限不每秒新建告警。
- **Topic：** `3d/v1/alarm`，对象内含 alarms 数组。
- **取数／封装：** 读取平台预警中心／告警业务对象，取稳定 alert_id、类型、标题、描述、严重度、时间、状态、关联对象／产品、原因、措施及责任人，按 alarms 定义组装；发布环节不重建预警规则或重新分配告警 ID。
- **转换：** 类型、严重度和状态按定义映射；未确认／未处理时间按定义为 null，关联对象保留编码与名称。未知原因或责任人不抄示例，缺失表达待确认。
- **全量规则：** 任一告警新增、确认、处理或内容变化后，发布约定范围内全部告警的完整 `{"alarms":[...]}`，不能只发该条。确无告警时发 `{"alarms":[]}`；获取失败不发假空集合，也不自行仅保留未处理告警。
- **边界：** 3D 发布只同步预警中心最新结果；唐车之家通知由平台通知逻辑负责，重复发布快照不再次通知责任人。

### 3.18 IF-3D-MQTT-016 缓存区详情与显示控制

**场景／策略：** 缓存位置的身份、占用和时长周期刷新；事件及初始化／恢复控制侧墙显示。周期同台位，先按 10 秒联调，实际值待定。

**Topic：** `3d/v1/buffer/{bufferCode}/data`，bufferCode 必须等于 staticAttributes.bufferID。

**取数／封装：** 基础信息取缓存位置主数据；产品身份、占用开始、侧墙类型和占用时长取平台缓存区对象最新状态。该状态由平台综合现场事件及产品关联维护，不在发布环节按收到消息数量推算缓存产品数量。

| bufferCode | 名称 |
| --- | --- |
| B-01、B-02、B-03 | 缓存1、缓存2、缓存3 |
| B-04、B-05 | 挂件1、挂件2 |
| STAGING-01 | 进料车 |
| STAGING-02 | 成品转运车 |

**方法：**

1. 七个位置分别发布完整 Payload，身份数组成对维护，显示指令规则同 3.13；bufferID 与 Topic 一致，bufferName 使用表中名称。
2. 缓存位置没有加工行为，仅发基础信息、身份／显示及缓存时长，不增加加工设备、加工起点或加工时长字段。
3. 空缓存的 productId／productName 同时为 `[]`，occupancyStartTime、carType、totalOccupancyDuration 为 null；初始化／恢复用 HIDDEN，周期用 KEEP。
4. STAGING-01／02 的显示指令只控制所载侧墙，不控制车体显隐或运动；车辆动画由原对应接口处理。carType 表达侧墙类型，不是车体类型。
5. 天车吊起／落放时由 3D 完成缓存区与挂载模型交接，平台不按动画时长补发显隐。

## 4. 联调步骤与完成标准

1. **取数验证：** 用已知 IOT 当前值及平台对象状态，核对来源、设备／机械手映射和时间。缺少真实对象样例时可先按业务含义准备明确标记的测试数据，不编造为生产事实。
2. **转换验证：** 检查状态枚举、JSON 类型、轴数组与字符串、整机聚合、Topic 编码；标定确认后再核验角度、方向、单位和场景位置。
3. **周期验证：** 按约定周期发布；设备基础信息保持不变时仍与动态值一起发送完整详情，面板关闭不影响后台发布。
4. **事件与全量验证：** 路径识别准确后发天车任务；两类车辆进入 true、离开 false；只改一个产品或告警时仍发全量集合，并验证确为空集与获取失败的区分。
5. **显示与交接验证：** 台位和七个缓存位置的身份数组成对；KEEP 更新业务信息不改显示，明确指令正确生效；天车完成模型交接后 KEEP 不恢复旧状态。
6. **初始化与恢复验证：** 待 API 定义并实现后，验证 3D 首次进入／重连主动查询最新对象状态，与 MQTT 更新衔接，周期 KEEP 不作为显示初始化。停用标签不启动任务。

**完成标准：** 来源数据变化后，平台能正确取数、转换、组装并按策略发布，3D 消费后对象、状态与动画效果正确。每个非停用接口有可追溯输入、Payload 和实际效果，不能仅凭手工消息发布成功验收；初始化 API 和标定未完成的内容分别记录为未完成，不宣称闭环通过。
