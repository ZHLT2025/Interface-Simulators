# 其他接口使用说明书

分册 V1.0｜2026-10-19｜1 项接口：唐车之家公众号消息推送

配套定义：[其他接口定义](../版本261017/接口定义说明书六、其他部分-唐车之家V10版公众号类消息推送接口.md)。完整报文查配套定义；本文新增的业务去重和调度方式为建议。

## 1. 任务范围

- **本平台角色：** 主动向唐车之家发送员工通知；没有接收回调或订阅任务。
- **输入：** 已确认业务通知、接收员工号、消息内容或业务页面链接。
- **输出：** 通知发送记录、响应标识和发送结果。
- **分工边界：** 业务方决定何事、何时通知谁；本任务完成发送和记录。接口接受不等于员工已收到或已读。

## 2. 连接与公共规则

| 配置 | 内容 |
| --- | --- |
| 接口 | IF-OTHER-001 唐车之家 V10 版公众号类消息推送 |
| 地址 | `http://appdoc.tangche.com:8080/MsgPush/servlet/PushServlet` |
| 请求 | POST，`application/x-www-form-urlencoded`，UTF-8；不是 JSON Body |
| 访问条件 | 来源 IP 获许可；环境归属及独立测试地址未明确 |
| 公众号 | pubNo=`cqszls` |
| 项目侧响应检查 | HTTP 2xx、可解析 JSON、pubId 与 sourceMsgId 均为非空字符串 |

**接收人必须明确。** userNo 空值会默认全公司推送。发送前拒绝空白、空列表项和未解析变量；多人用英文逗号连接，保留工号前导零。

## 3. 各接口使用方法

### 3.1 IF-OTHER-001 的触发策略

| 场景 | 何时调用 | 建议去重依据 |
| --- | --- | --- |
| 事件通知 | 告警、关键生产节点或待处理事项已确认并保存后 | 业务对象＋通知阶段＋接收人集合 |
| 定时摘要 | 业务配置的班次／日报节点，统计数据就绪后 | 统计期＋模板＋接收人集合 |
| 人工单次发送 | 有权限人员预览并提交后 | 一次提交对应一个任务，避免连点重复 |

每个任务发送一次后结束。不要对每条 IOT／CV／3D 消息都发通知；严重度、合并与重复提醒间隔由业务规则确定。

### 3.2 模式与具体方法

| msgType | 适用场景 | 参数重点 | 不提交 |
| --- | --- | --- | --- |
| 2 | 简短纯文本 | userNo、pubNo、text；title 无效，可省略 | url、htmlText |
| 5 | 点击打开业务详情 | userNo、pubNo、title、text、完整 url | htmlText |
| 6 | 点击查看静态 HTML 摘要 | userNo、pubNo、title、text、htmlText | url |

1. 保存通知任务，校验员工号、模式及内容；摘要明确统计期和数据截至时间。
2. 使用表单编码库编码一次；HTML 中业务文本先转义，再进行表单传输编码，避免重复编码。
3. 发送并检查响应，保存 pubId、sourceMsgId、接收人和发送时间，标记“接口接受”。
4. 正式业务链接应是接收人可以访问的页面；请求成功与页面可访问分别验证。

### 3.3 失败与恢复

- 参数或 IP 权限错误先修复，不持续重复发。
- 超时、连接中断或 2xx 缺响应标识时标记“结果不确定”，核查实际投递后再决定重发，避免重复通知。
- 本接口没有请求幂等字段。sourceMsgId 是响应值，不能自行作为请求去重键。
- 服务恢复时继续未发送任务；结果不确定的任务先核查，不批量盲目重发。
- 未定义送达／已读回执及查询接口，不轮询发送接口等待回执，不假定多人全部送达。

## 4. 联调步骤与完成标准

1. 核实来源 IP 许可和一个真实测试员工号，先验证空工号会被平台拦截。
2. 分别测试纯文本、链接、HTML 三种模式，检查中文与特殊字符编码。
3. 在接收端验证文本、跳转及 HTML 展示；记录接口响应和实际效果。
4. 验证重复提交去重、发送失败和结果不确定的处理。

**完成标准：** 三种模式可用，接收人准确，发送记录可追溯；响应成功、送达和已读不混淆。可用明确测试通知独立联调，再接入真实业务事件。

## 5. 待确认事项

| 问题 | 确认方／影响 |
| --- | --- |
| 环境归属、来源 IP 许可、正式接收范围 | 唐车之家管理员；决定实际联调配置 |
| 消息长度、接收人数、HTML 大小与标签／样式支持 | 提供方；决定内容和批量组织 |
| 正式响应规则、调用频率及超时后的投递核查方式 | 提供方；决定成功判断与重发 |
| 通知触发、摘要时点、接收人、升级和重复提醒规则 | 业务方；作为通知配置交付，不在接口中猜测 |
