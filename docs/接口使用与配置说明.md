# 外部接口模拟器 接口使用与配置说明

版本：V1.0 ｜ 日期：2026-10-26 ｜ 面向：第三阶段（测试实例装载）与第四阶段（集成测试）执行者

## 1. 服务入口

部署主机 `185.189.48.12`，所有服务绑定 `0.0.0.0`，已从海外节点验证可达（见 `docs/evidence/public-reachability-check-host.txt`）。

| 模拟对象 | 协议 | 公网入口 | 契约路径 | 认证 |
| --- | --- | --- | --- | --- |
| MOM | HTTP/JSON | `http://185.189.48.12:18001` | `POST /api/v1/get_orderlist`、`POST /api/v1/get_order` | HTTP Basic（`MOM_BASIC_USER/PASS`） |
| IoT HTTP | HTTP/JSON | `http://185.189.48.12:18002` | `GET /open/deviceList`、`POST /open/deviceParamList`、`POST /open/deviceHistory/getDeviceData`、`GET /open/sendConfig/list`、`PUT /open/sendConfig/fullUpdate` | 请求头 `X-Factory-Code: BJZHLT`（无账号认证，按定义） |
| IoT MQTT | MQTT 3.1.1/TCP | `mqtt://185.189.48.12:18830` | Topic `pushToFactory/BJZHLT/device/{deviceCode}`，QoS 0，Retain false | 用户名/密码（订阅账号 `IOT_MQTT_SUB_USER/PASS`，只读） |
| ESB | SOAP 1.1/XML | `http://185.189.48.12:18003` | `POST /ESB/SAP/SAP_MaterialAndDocumentNewQuery[/1.0.0]`、`POST /ESB/WINDCHILL/WINDCHILL_GeneralInterface` | HTTP Basic（`ESB_BASIC_USER/PASS`） |
| CV（发送器） | HTTP/JSON 客户端 | 控制面 `http://185.189.48.12:18004/_sim/cv/*` | 向 `CV_TARGET_URL` 主动 `POST /api/v1/cv-events` | 目标端 Basic（`CV_TARGET_BASIC_USER/PASS`） |
| CV（验证接收端） | HTTP/JSON | `http://185.189.48.12:18004` | `POST /api/v1/cv-events`（验证用，非平台） | HTTP Basic（`CV_SINK_BASIC_USER/PASS`） |

所有凭据只存在于服务器 `/root/project/interface-simulators/.env`（权限 600，git 忽略）。本文档与报告不记录明文。查看方式：`grep _PASS /root/project/interface-simulators/.env`。

每个 HTTP 服务的根路径 `GET /` 返回该模拟器的契约清单；`GET /_sim/health` 无需认证。

## 2. 启动、停止、重新部署

```bash
cd /root/project/interface-simulators
./deploy/init-env.sh            # 首次：生成 .env 与 MQTT 密码文件（已执行；--force 可重新生成全部凭据）
./deploy/up.sh                  # 构建镜像并启动 5 个容器（sim-mom/sim-iot/sim-esb/sim-cv/sim-mqtt）
./deploy/restart.sh [服务名...] # 代码修改后重建并重启（默认 mom iot esb cv）
./deploy/down.sh                # 停止并删除容器（数据集、.env、state/ 保留）
docker compose ps               # 查看状态（healthcheck）
docker compose logs -f sim-iot  # 查看日志
```

容器设置 `restart: unless-stopped`，宿主机重启后自动拉起。`.env` 修改后必须 `docker compose up -d`（不能只 `restart`）。

## 3. 管理与观测接口（`/_sim/*`，契约之外）

所有 `/_sim/*`（除 `health`）要求请求头 `X-Sim-Admin-Token: <SIM_ADMIN_TOKEN>`。

| 路径 | 作用 |
| --- | --- |
| `GET /_sim/status` | 当前数据集、策略开关、计数、（IoT）发布器状态 |
| `GET /_sim/requests?n=50&path=/api` | 最近请求/响应记录（请求头 Authorization 已脱敏），可作为联调证据 |
| `POST /_sim/reload` | 重新读取当前数据集（IoT 会恢复数据集中的推送配置并重置脚本） |
| `POST /_sim/dataset` `{"name":"<目录名>"}` | 切换到 `<sim>/data/<目录名>/` 数据集 |
| IoT `GET /_sim/mqtt/status`、`POST /_sim/mqtt/pause|resume`、`POST /_sim/mqtt/publish`、`POST /_sim/mqtt/script/reset` | 发布器控制、手工发布任意 Payload |
| CV `POST /_sim/cv/emit`、`/_sim/cv/emit-raw`、`/_sim/cv/build`、`/_sim/cv/scenario/run|stop|status`、`GET /_sim/cv/status` | 事件生成与发送、剧本执行 |
| CV `GET /_sim/cv/sink/events`、`POST /_sim/cv/sink/clear`、`POST /_sim/cv/sink/fail-mode` | 验证接收端已收事件、清空、模拟 500 |
| CV `GET /_sim/cv/evidence/{event_id}/frame_001.jpg` | 下载事件证据图（无需认证，SHA-256 与报文一致） |

## 4. 数据集与测试实例替换（第三阶段接手点）

每个模拟器从 `<sim>/data/<数据集>/` 读取 JSON，默认数据集 `sample`（协议验证样例，**不是正式剧本**）。替换测试实例的方法：

1. 复制 `sample` 为新目录，例如 `mom/data/wall-D07126010008Q/`，按相同文件结构填入实例数据；
2. 通过 `.env` 的 `SIM_DATASET=<目录名>`（或单独 `MOM_DATASET/IOT_DATASET/...`）后 `docker compose up -d`，或运行中调用 `POST /_sim/dataset`；
3. 不需要修改任何接口通信代码。

| 模拟器 | 文件 | 内容 |
| --- | --- | --- |
| MOM | `orders.json` | `orders[]`，每条 `{list:{IF-MOM-001 列表字段（数值型）}, detail:{IF-MOM-002 的 MOMWIPORDER 对象（字符串型）}}`；列表过滤依据 `list.WORKCENTER` 与 `list.LASTUPDATEON`（ISO 8601，无时区） |
| IoT | `devices.json` | IF-IOT-001 设备清单 |
| IoT | `params.json` | IF-IOT-002 每设备参数清单（`paramType` 决定生成器默认类型） |
| IoT | `history.json` | IF-IOT-003 历史种子 `records[]{deviceCode,paramCode,historyData[]}`；运行时发布的实时样本自动追加 |
| IoT | `send_config.json` | IF-IOT-004 初始推送配置；被 IF-IOT-005 更新后保存在 `state/iot/send_config.json`，`/_sim/reload` 恢复 |
| IoT | `realtime.json` | MQTT 发布规则：`mode=generator`（按 `generators` 随机游走，只发变化点位，`change_probability` 控制变化比例）或 `mode=script`（`script[]{at秒, deviceCode, points[]}` 定时回放，`loop` 循环） |
| ESB | `sap_docs.json` | `materials[物料号] = DOCS.item[]`；同一 DOKNR 多条取最后一条或 `latest:true` |
| ESB | `windchill_docs.json` | `documents[文档号] = URL`；未列出 → `文档不存在！` |
| CV | `catalogue.json` | 摄像机、ROI（`id`、`area_name`）及各事件类型默认 `targets` |
| CV | `scenarios.json` | `scenarios[名称].steps[]`，每步字段同 `/_sim/cv/emit` 的 spec，`at` 为相对秒 |

### 时间平移说明

模拟器不做自动时间平移：MOM/IoT 历史按数据集中的时间串原样比较；MQTT 实时样本与 CV 事件使用当前时间（IoT 按 `SIM_TIMEZONE`，CV 按 UTC）。第三阶段若需要把剧本时间平移到测试日，应在生成数据集文件时完成（或在 CV spec 中显式给出 `timestamp`、在 IoT `/_sim/mqtt/publish` 中显式给出 `serverTime/sourceTime`）。

## 5. 各接口调用示例

以下 `$MOM_USER` 等变量请从 `.env` 读取。

```bash
curl -u "$MOM_BASIC_USER:$MOM_BASIC_PASS" -H 'Content-Type: application/json' \
  http://185.189.48.12:18001/api/v1/get_orderlist -d '{
  "esbInfo":{"instId":null,"requestTime":"2026-07-30 16:36:50","attr1":null,"attr2":null,"attr3":null},
  "requestInfo":{"SYSTEMTYPE":119,"STARTTIME":"2026-07-28 00:00:00","ENDTIME":"2026-07-30 16:00:00","WORKCENTER":"TS36120201","DEVICEPN":null}}'

  http://185.189.48.12:18001/api/v1/get_order -d '{
```

### 5.3 IoT MQTT 订阅（定义 23.6.2 形式）

```bash
mosquitto_sub -h 185.189.48.12 -p 18830 -V mqttv311 -i if-23-sub-test \
  -u "$IOT_MQTT_SUB_USER" -P "$IOT_MQTT_SUB_PASS" -t 'pushToFactory/BJZHLT/device/cqx11' -q 0 -v
```

### 5.5 CV 事件发送

```bash
A="X-Sim-Admin-Token: $SIM_ADMIN_TOKEN"
# 生成并发送一条合同报文（目标 = CV_TARGET_URL，默认为自带验证接收端）
curl -H "$A" -H 'Content-Type: application/json' http://185.189.48.12:18004/_sim/cv/emit \
  -d '{"event_type":"PERSON_COUNT","camera_id":"CAM-20","roi_id":"ROI_20_01_02"}'
# 侧墙翻转，显式字段
curl -H "$A" -H 'Content-Type: application/json' http://185.189.48.12:18004/_sim/cv/emit \
  -d '{"event_type":"WALL_FLIP","camera_id":"CAM-20","roi_id":"ROI_20_02_01","wall_state":"vertical","state_sequence":["horizontal","vertical"]}'
# 指向其他接收端 / 使用其他凭据（例如平台的接收服务）
curl -H "$A" -H 'Content-Type: application/json' http://185.189.48.12:18004/_sim/cv/emit \
  -d '{"event_type":"SPARK","camera_id":"CAM-21","roi_id":"ROI_21_01_01","target_url":"https://185.189.48.12:5100/api/v1/cv-events","target_user":"<凭据ID>","target_pass":"<密钥>"}'
# 原样发送任意报文（负向测试/回放）
curl -H "$A" -H 'Content-Type: application/json' http://185.189.48.12:18004/_sim/cv/emit-raw -d '{"payload":{...}}'
# 运行剧本
curl -H "$A" -H 'Content-Type: application/json' http://185.189.48.12:18004/_sim/cv/scenario/run -d '{"name":"all-types"}'
curl -H "$A" http://185.189.48.12:18004/_sim/cv/scenario/status
```

`spec` 字段：`event_type`（必填，13 类之一）、`camera_id`、`roi_id`、`roi_name`、`timestamp`（ISO UTC 毫秒）、`targets[]`、`count`、`wall_state`、`state_sequence`、`operation`、`event_id`（默认自动 Snowflake）、`target_url`、`target_user/target_pass`。发送结果 `delivery.outcome` 取值：`success`、`auth_failed`（401 不重试）、`rejected_422`（不重试）、`server_error`/`network_error`（已按配置重试）、`ambiguous`（HTTP 200 但响应体不符合定义）。

把发送器指向平台正式接收端：在 `.env` 设置 `CV_TARGET_URL`、`CV_TARGET_BASIC_USER/PASS`、必要时 `CV_TLS_VERIFY=false`，然后 `docker compose up -d cv`。
