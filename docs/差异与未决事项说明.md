# 差异与未决事项说明（第一阶段）

版本：V1.1 ｜ 日期：2026-10-27（V1.0：2026-10-26）｜ 适用：`/root/project/portal-20261022/interface-simulators/`

> V1.1：补充 I19（历史与 MQTT 发布关系，F03）、C12（证据 URI 与图片地址，F05）、第 7 节部署层访问控制（F02）。

本说明把模拟器行为分成四类，便于后续阶段判断哪些行为可直接作为测试预期、哪些需要客户方确认：

| 标记 | 含义 |
| --- | --- |
| **A 已确认** | 接口定义说明书明确规定或给出真实报文，模拟器严格实现 |
| **B 实测参考** | 定义中标注"实测结论/待提供方确认"的行为，模拟器按实测实现 |
| **C 暂定实现** | 定义未规定（多为失败返回、边界语义），模拟器采用技术上合理的可辨识默认值，**可通过环境变量切换**，不代表客户正式规则 |
| **D 未决缺口** | 无足够依据实现，模拟器不做猜测；需要客户方确认后在第二/三阶段补充 |

Authority 顺序：接口定义说明书 > 接口使用说明书 > 现有 S01 实现。定义与使用说明冲突时以定义为准，差异保留并可配置。

## 5. 与现有消费者（YQYD S01）的只读分析结论

以下为只读检查结果，**本轮未修改 YQYD/STM/BOS/Portal 任何源码或配置**；S01 不兼容项仅记录，修改另行授权。

| # | 发现 | 影响 |
| --- | --- | --- |
| S1 | YQYD runtime 容器 `network_mode: none`，仅通过 unix socket 经 edge nginx 对外；无法访问本机端口或任何 Docker 网络 | S01 现状无法直接调用公网模拟器（MOM/IoT HTTP/MQTT）。需要在第四阶段前由另行授权的变更解决（如 socket 桥接或网络模式调整） |
| S2 | S01 MOM 适配器始终发送 4 个工位之一的 `WORKCENTER`，`SYSTEMTYPE` 在 001 为 Number、002 为 String | 与定义及模拟器默认策略一致 |
| S3 | S01 IoT 适配器按定义发送 `X-Factory-Code`/`Accept`，不发认证；成功判定 `success===true && code===0` | 与模拟器一致 |
